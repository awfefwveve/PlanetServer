# PlanetServer — 에버플래닛 스타일 MMORPG 서버 (C# / .NET 10)

러쉬에잇 [에버플래닛] 서버 프로그래머 공고의 기술 스택에 맞춰 직접 만든 학습용 MMORPG 서버입니다. 원작 서버 코드나 데이터를 가져온 것이 아니고, 공개 영상에서 보이는 기능을 보고 독립적으로 구현했습니다. Unity 클라이언트는 원작 화면을 참고한 이미지가 들어 있어 이 저장소에는 넣지 않았습니다.

## 한눈에

- **스택:** C# / .NET 10 · TCP + TLS 지속 연결 · Protobuf · PostgreSQL · Unity 6 클라이언트
- **구현:** 로그인·캐릭터 생성 · 채널 30개(정원·자동 배정) · 지역 포탈 · 100ms 서버 틱 + 상태 푸시 · 몬스터 AI(비선공→추적→귀환) · HP/MP·사망·부활·경험치 · 가방 24칸·장비 4부위 · 스킬 3종 · NPC 상점 · 플레이어 거래 · 파티(경험치 분배) · 채팅(방/파티/귓말)
- **테스트:** 기능·장애 테스트 314개 (PostgreSQL 포함) · 부하 측정 50~1,000 클라이언트 ([docs/LOAD_TEST.md](docs/LOAD_TEST.md))

## 핵심 설계 5가지

1. **연결 구조** (`GameHost.cs`) — 연결마다 읽기/쓰기 루프를 나누고 보낼 패킷 큐를 64개로 제한했습니다. 느린 클라이언트 하나가 서버 전체를 막지 못하게 큐가 넘치면 그 연결만 끊습니다. 패킷은 4바이트 길이 + 최대 32KB.
2. **저장 먼저, 반영 나중** (`World.cs`) — 몬스터를 잡으면 보상을 먼저 DB에 저장하고, 저장이 성공해야 몬스터가 죽습니다. 저장이 실패하면 몬스터도 살아 있고 보상도 없습니다. 서버가 죽어도 "보상만 받거나 몬스터만 죽는" 상태가 생기지 않습니다.
3. **잠금 순서** — 계정 게이트(256개로 분산) → 채널 게이트(번호 순)로 항상 같은 순서로 잡습니다. 거래·파티처럼 여러 사람이 엮여도 교착 상태가 생기지 않습니다.
4. **중복 요청 차단** — 요청마다 순번(Sequence)을 붙여 재전송을 거부하고, 몬스터 ID에 부활 번호를 붙여 "이미 죽은 몬스터를 다시 때리는" 요청을 막습니다. 귓말·파티·시스템 메시지는 세션 우편함으로 정확히 한 번 전달합니다.
5. **관계형 저장** (`PostgresStore.cs`, [docs/DATABASE.md](docs/DATABASE.md)) — 계정·캐릭터·가방 칸·장비·스킬을 테이블 5개로 나눴습니다. 저장 한 번이 트랜잭션 하나이고, 계정 revision으로 오래된 저장이 최신 상태를 덮어쓰지 못하게 합니다. 거래는 두 계정을 한 트랜잭션으로 저장해 아이템 복사·증발을 막습니다.

## 직접 검토하고 고친 것

AI 코딩 도구(Codex, Claude)로 구현 속도를 내고, 결과물은 제가 공고 요구사항과 대조하며 검토했습니다.

| 문제 | 원인 | 바꾼 것 | 확인 |
|---|---|---|---|
| DB가 계정을 JSON 한 덩어리로 저장 → 테이블·인덱스 설계가 없음 | 파일 저장을 그대로 DB 한 칸에 옮긴 지름길 | 테이블 5개, 기본키·외래키·CHECK·UNIQUE, 아이템 인덱스, 옛 데이터 자동 이관 | PostgreSQL 테스트 20개 추가 |
| 리눅스에서 대소문자가 다른 계정을 못 찾음 | 로그인은 소문자로 찾는데 파일 저장은 원래 이름으로 저장. 윈도우는 대소문자를 무시해서 안 보였음 | 두 저장소 모두 소문자 키로 통일 | 기존 실패 테스트 통과 |
| 접속 받기에서 오류가 한 번만 나도 서버 전체가 꺼지고 게임 중인 플레이어가 모두 끊김 | 접속 받기(`AcceptTcpClientAsync`) 예외를 아무도 안 잡아서 `Run()`이 끝나고, `Program.cs`가 이를 서버 종료로 처리 | `AcceptNext`에서 `SocketException`만 잡아 로그를 남기고 100ms 뒤 다시 받음. 종료 요청일 때만 멈춤 | 실패 재시도·종료 테스트 2개 추가 |

## 테스트와 한계

- 통과: 기능·장애 테스트 314개. 저장 실패, 오래된 revision, 동시 보상 요청, 만원 채널, 거래 충돌 같은 실패 경우를 직접 재현합니다(`FaultStore`, `DelayedStore`).
- 부하: 같은 PC에서 서버와 부하 생성기를 따로 띄워 측정했습니다. 1,000 클라이언트 요청 중 691개가 끝까지 활동했고 나머지는 접속 단계에서 끊겼습니다. 상용 수용량 수치가 아니며 원인 분석이 다음 작업입니다.
- 아직 없음: 시야 범위(AOI) 필터링, 재접속 복구, 배포·모니터링.

## 실행

```sh
# 테스트 (PostgreSQL 없이 294개)
dotnet run --project tests

# PostgreSQL 포함 314개
docker compose up -d
PLANET_TEST_DB="Host=127.0.0.1;Port=55432;Username=planet;Password=planet-local-dev-only;Database=planet" dotnet run --project tests

# 서버 (127.0.0.1:7777, PLANET_DB를 주면 PostgreSQL 사용)
dotnet run --project src/Server
```
