# Little Planet Online — 서버 포트폴리오 기반

에버플래닛 서버 채용 공고를 기준으로 시작한 독립 학습 프로젝트입니다. 원작의 구현이나 콘텐츠를 복원한 결과물이 아닙니다. 현재는 Unity 6 클라이언트와 C#/.NET 서버를 연결한 작은 플레이 흐름입니다. 그래픽과 수치는 모두 임시 자체 제작입니다.

## 실행

1. `PlayServerDemo.cmd`를 실행합니다. 서버가 로컬에서 시작되고 게임 창이 열립니다.
2. 영문 소문자·숫자·밑줄로 3~16자 이름과 8자 이상의 테스트용 비밀번호를 입력합니다. 처음 쓰는 이름이면 계정이 만들어집니다.
3. WASD로 이동하고 슬라임 가까이에서 Space로 공격합니다.
4. 세 마리를 처치한 뒤 E 또는 보상 버튼을 누릅니다. 슬라임은 처치 후 3초 뒤 다시 나타납니다.
5. 연결 해제 후 같은 이름·비밀번호로 다시 접속하면 처치 수, 조각, 골드, 보상 수령 상태가 유지됩니다.
6. 다른 플레이어를 함께 보려면 첫 게임을 켠 상태에서 `SecondClient.cmd`를 실행하고 다른 이름으로 접속합니다.

첫 게임 창을 닫으면 실행기가 서버를 정상 종료합니다. 두 번째 게임 창도 직접 닫아주세요. 외부 네트워크에는 서버를 열지 않으며 `127.0.0.1:7777`만 사용합니다.

기본 실행은 로컬 JSON 저장입니다. 서버 재시작은 지원하지만 운영용 DB 내구성과 같지 않습니다. 데이터와 로그는 `data/`에 생성됩니다. TLS 인증서의 지문을 실행기가 클라이언트에 전달합니다. 인증서를 무조건 신뢰하는 우회는 사용하지 않습니다.

## PostgreSQL로 실행

Docker를 켜고 프로젝트 폴더에서 `docker compose up -d`를 실행합니다. 로컬 55432 포트가 비어 있어야 합니다. 이번 검증에서는 Docker 이미지 다운로드가 실패해 별도 Windows PostgreSQL로 테스트했으며, 그 테스트 DB는 종료했습니다.

```powershell
$env:PLANET_DB='Host=127.0.0.1;Port=55432;Username=planet;Password=planet-local-dev-only;Database=planet;Timeout=5;Command Timeout=5'
.\scripts\Play.ps1 -Postgres
```

위 비밀번호는 로컬 개발 예제입니다. PostgreSQL 모드와 JSON 모드는 별도 저장소이며 자동으로 데이터를 이전하지 않습니다. 첫 실행은 `planet_accounts` 테이블을 생성합니다. 현재 스키마는 계정별 JSONB 스냅샷과 revision 비교를 쓰는 초안입니다. 운영용 정규화 스키마·원장·마이그레이션은 후속 작업입니다.

## 개발과 검증

- Unity 6000.3.25f1, .NET SDK 10으로 빌드했습니다.
- `scripts/Build.ps1`: 프로토콜 생성 → Unity 의존 DLL 복사 → 독립 실행 가능한 서버 배포 → Windows 클라이언트 빌드.
- `scripts/Test.ps1`: 서버 규칙, 파일 저장, 실제 TCP/TLS/Protobuf 통합 검증.
- PostgreSQL 테스트는 `PLANET_TEST_DB`에 별도의 테스트 DB 연결 문자열을 지정하면 추가 실행됩니다. 테스트 계정이 해당 DB에 남습니다.
- `src/Protocol/planet.proto`: 공통 패킷 원본. Unity의 `Assets/Plugins/Protocol.dll`은 빌드 산출물이므로 직접 수정하지 않습니다.

현재 컴퓨터에는 빌드 SDK를 작업 폴더의 `work/dotnet`에 설치했습니다. 다른 컴퓨터에서는 .NET 10 SDK와 Unity가 필요합니다. 완성된 `build` 폴더로 플레이만 할 때는 SDK가 필요하지 않습니다.

## 구현 범위

- 계정 생성·인증, 비밀번호 PBKDF2 해시, 중복 로그인 거부.
- TCP 길이 프레임, TLS, Google Protobuf 생성 코드, 프레임 크기·요청 빈도 제한.
- 두 명 이상 접속, 서버 권한 이동·거리·공격 재사용 대기시간 검증.
- 슬라임 처치, 조각 지급, 3회 처치 퀘스트, 1회성 100골드 지급.
- 보상을 저장한 뒤에만 성공 상태를 반영. revision 충돌로 이전 상태 덮어쓰기 방지.
- 로컬 파일 저장 및 PostgreSQL 저장 구현.
- 둥근 표면에 평면 논리 좌표를 표시하는 임시 Unity 장면.

## 현재 한계

이 결과물은 라이브 서비스 준비가 된 MMORPG가 아닙니다. 최대 16연결의 단일 맵 시험 서버입니다. 약 10Hz 요청/응답으로 전체 상태를 받으며, 서버 푸시·AOI·채널·분산 처리는 없습니다. 모든 월드 변경과 DB 작업을 하나의 비동기 잠금 안에서 직렬 처리하므로 느린 DB는 전체 맵에 영향을 줍니다. 정확성을 확인하는 첫 단계의 선택이며 부하 검증 후 분리해야 합니다.

몬스터는 제자리 표적이고 전투 AI·플레이어 HP·인벤토리 슬롯·직업·스킬·원작 맵·소셜·운영 도구는 아직 없습니다. 이동 좌표는 정상 연결 종료 또는 보상 저장 때 함께 저장되며, 강제 종료 직전의 이동은 유실될 수 있습니다. 몬스터 상태는 재시작 시 초기화됩니다. 공개 가입 방어, IP별 인증 제한, 비밀번호 복구, 개인정보 정책, 배포 자동화, 백업 복원·대규모 부하 시험도 남아 있습니다.

인증서 고정은 로컬 개발 편의 기능입니다. 공개 서비스는 도메인·정상 인증서 검증·갱신·인증 정책을 다시 설계해야 합니다. 파일 저장은 한 프로세스만 사용해야 하며 실행기가 데이터 폴더 잠금을 사용합니다. PostgreSQL 역시 현재 하나의 월드 프로세스만 실행하는 것을 전제로 합니다.
