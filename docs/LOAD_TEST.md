# 부하 테스트

코드: `tools/LoadProbe/Program.cs` · 결과: `load-results/*.json`

## 실행

```sh
# 인원 · 측정 초 · 결과 파일 · 시나리오(crowded | spread)
dotnet run --project tools/LoadProbe -- 200 20 load-results/200-crowded.json crowded
dotnet run --project tools/LoadProbe -- 1000 20 load-results/1000-spread.json spread
```

- `crowded`: 모두 한 채널·한 지역에 몰아넣음. `spread`: 채널 30개에 고르게 나눔.
- 게임 서버를 따로 켤 필요가 없습니다. 도구가 임시 포트로 테스트 서버를 별도 프로세스로 띄우고, 끝나면 내립니다. 서버 코드는 실제 서버와 같고, 채널 정원만 요청 인원에 맞춥니다.

## 무엇을 재나

가짜 클라이언트가 실제 TCP/TLS로 접속해 Protobuf로 로그인 → 채널 입장 → 이동·상태 조회를 번갈아 보냅니다. 응답을 받을 때마다 100ms 쉬고 다음 요청을 보내므로 클라이언트 하나당 최대 초당 10개입니다(응답이 늦으면 부하도 같이 줄어드는 방식).

전투·보상·채팅·포탈·DB 저장 부하, 패킷 지연·유실, 장시간 운영은 이 도구로 재지 않습니다.

## 결과 (15~20초 측정)

| 조건 | 끝까지 활동 | p99 응답 | 초당 응답 | 오류 |
|---|---|---|---|---|
| 200명 한 지역 | 200 | 7.75ms | 약 1,848 | 0 |
| 500명 한 지역 | 500 | 34.51ms | 약 4,139 | 0 |
| 1,000명 30채널 분산 | 1,000 | 13.29ms | 약 9,116 | 0 |
| 1,000명 한 지역 | 691 | 538.87ms | - | 309명 접속 단계에서 끊김 |

서버와 부하 생성기를 프로세스는 나눴지만 같은 PC에서 돌렸고 네트워크 지연도 없습니다. 실제 서비스 수용량으로 바꿔 읽을 수 있는 숫자가 아닙니다.

## 1,000명 밀집에서 끊긴 이유 (추정)

서버 로그에 `InvalidDataException`이 309건 있었습니다. 상태 응답(`World.Snapshot`)은 같은 지역의 플레이어 전원을 매번 담는데, 패킷 하나의 상한은 32KB입니다(`Framing`). 사람이 많아지면 응답이 이 상한을 넘는 것으로 보고 있습니다. 실패한 응답의 크기를 기록해서 확인하는 게 다음 작업입니다.

상한을 늘리는 것만으로는 해결이 아닙니다. 근처 플레이어만 보내기(AOI)나 바뀐 것만 보내기(차분 전송)가 맞는 방향이라고 봅니다.
