구현 단계: 캐릭터 능력치 기반 / 도착 연출 / 개발 정원 — 2026-10-11

사용
게임에서 C키 또는 하단 캐릭터 아이콘 → 캐릭터 상태창.
HP/MP/레벨/경험치/공격력/방어력은 서버의 Update.self_stats를 읽는다.
새 캐릭터는 meadow 부두(-6.2,-2.2)에서 시작하고 비행 도착 연출을 본다.
기존 저장 위치는 변경하지 않는다. 부두가 아닌 위치에서 재접속하면 필드로 바로 들어간다.

공부 순서
1. UiBootstrap: 입력 C → PreviewUiController.Open(CharacterStatus).
2. CharacterCatalog: 생성 시 CharacterProgress 초기값을 캐릭터에 저장.
3. Storage: 계정 JSON/JSONB 속 캐릭터 Progress를 저장. 기존 데이터는 null일 때 기본값 적용.
4. CharacterStatsRules: 저장 상태에서 표시할 최대HP/MP/경험치 상한 등을 서버에서 계산.
5. World.Snapshot: 자신의 능력치만 self_stats에 넣는다. 모든 플레이어 목록에 중복하지 않는다.
6. planet.proto: CharacterStats 메시지 → 생성된 Protocol.dll을 Unity가 사용.
7. PreviewUiController.Present: Model.Stats 갱신 → GameHudView와 CharacterStatusView가 같은 값을 표시.
이 순서로 브레이크포인트를 걸면 버튼/서버/저장/응답/화면 관계를 추적할 수 있다.

범위
기본HP275/MP60, 공격력1/방어력0, 레벨별 최대치 공식은 포트폴리오 초기 규칙이다.
원작 수치 검증 결과가 아니다. 레벨업·경험치 획득·스킬 습득/소모·몬스터 피해는 아직 추가하지 않았다.
현재 일반 공격은 기존1피해이며 상태창 공격력도1이다. 증가된 공격력으로 전투하는 시스템은 다음 단계다.
캐릭터 상태창은 기능 구현용 UI이며 원작 상태창 디자인을 완전히 재현한 것은 아니다.
다음 단계: 처치 경험치 → 레벨업 → 저장 실패 시 보상 미반영 → 재접속 유지 검증.
이후 스킬1개(습득/포인트/MP/거리/쿨다운/피해/연출)를 끝까지 연결한다.

비행
ArrivalRoute는 부두 기준 베지어 경로를12초 동안 이동하고 마지막 구간에서 감속한다.
PreviewWorld는 경로 뒤를 따라가되 카메라 방향은 고정한다. 남은 시간에 높이를 낮춰 착륙한다.
ArrivalMotion은 월드 비행 좌표를 화면 좌표로 투영하므로 화면 한 위치에 고정된 연출이 아니다.
사용 중인 비행선은 기존2D 이미지이며 3D 기체 모델을 새로 만든 것은 아니다.
게임플레이의45도 카메라/곡률/UI 배율은 유지했다. 부두 판자 높이를 캐릭터 발 위치에 반영했다.

정원
채널 기본정원32 →1000, 서버 전체 기본동시접속128 →1000.
PLANET_CHANNEL_CAPACITY, PLANET_MAX_CONNECTIONS 환경변수가 있으면 해당 값이 우선한다.
30개 채널 각각1000이라고 해서 단일 서버프로세스가30000을 수용하도록 바꾼 것이 아니다.
원작 정원이1000이었다는 확인도 아니며 사용자가 지정한 개발 목표다.
이전 밀집 부하 실패(AOI/차분전송/프레임상한)는 해결하지 않았다. 정원은 성능 보증이 아니다.

검증
서버151 assertions PASS (PostgreSQL 통합검사는 이번 실행에서 환경변수가 없어 제외).
실제 TLS 로그인→생성→입장→도착연출→상태창/HUD→채팅→채널전환→저장19항목 통과.
기존 데이터 호환, Progress 저장/재조회, 채널1000표시를 검사했다.
사용자 수정 HemisphereAuthoring.unity는 덮어쓰지 않았다.
서버 재시작 후 기존 캐릭터 입장/저장 위치/능력치/UI/채널 변경14항목도 통과했다.
